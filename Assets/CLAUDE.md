# Blockpet（簡化版）— 給 Claude Code 的專案說明

這是一款用手機照片養寵物的社交手遊。Unity 2D，直式手機。
玩家用自己相簿裡的照片當手牌，出牌餵給房間共用的寵物；寵物依照片類別給回饋、進化；餵出去的照片自動分享到營地，大家可以留言。

## 工作方式

- 介面設計以 claude.ai 設計檔「Blockpet 簡化版遊戲畫面」的「首頁 v8 照片分割」為準（https://claude.ai/artifact/BhqLuHp9n1MniNXyypAYim）。

- 用繁體中文回覆、寫註解與 UI 文字。
- 不要把整段程式碼貼在對話裡，直接修改專案檔案。
- 改動前先讀既有程式，延用既有寫法，不要重寫已完成的系統。

## 現有程式（2026-10-17 盤點，Unity 2022.3.62f3、URP、Firebase）

- 可直接沿用：`FirebaseManager`（Google／Apple／訪客登入、Realtime Database）、`ChatUIHandler`／`ChatMassage`（聊天室，目前寫在 `ChatRoom` 節點）、`CameraController`（WebCamTexture 拍照）、`AlbumUI`（相簿依日期分組）、`PetAnimationEvents`、`FeedController`（餵食動畫流程）、`EconomyManager`（金幣與數字跳動 UI）。
- 需要改：
  - 所有遊戲資料目前存在手機本地（`SaveManager` 的 save.json、`PlayerPrefs`）。寵物、愛心、金幣、照片動態要改成存在 Firebase 的房間底下，讓成員共用。
  - `PetHealthManager`：目前是 24 小時連續秒數、用手機時間計算；改成 0～5 顆（半顆為單位）、每 5 小時 −0.5、伺服器時間。
  - `EconomyManager`：目前每張固定 +50、存個人 PlayerPrefs；改成 +1／+5×愛心乘數，存房間帳戶。
  - `CameraController`：拍照冷卻保留（2026-10-29 改成 10 分鐘）；沒有每日張數限制。
  - `PetCollectionManager`：集滿後隨機換寵物是佔位邏輯，之後換成進化分支與孵化。
  - `BulletinManager`（7 張照片看板）：改成營地最新照片與分割畫面。
  - 聊天室要從全域 `ChatRoom` 改到各房間底下。
- 目前沒有「房間」的資料結構，需要新增。
- 發酵桶已於 2026-10-17 移除；舊程式裡沒有角色身份、7/3 分帳，不用清理。
- 寵物移動使用既有的 NavMeshPlus 設定。
- 一次只做一個任務；做完說明改了哪些檔案、如何在 Editor 測試。
- 遇到下方「待定」的規則，先問我，不要自己決定。

## 已定案的遊戲規則

### 照片與手牌
- 照片五大類別：美食、自然、城市、生活人物、寵物（2026-10-29：運動戶外併入自然，新增寵物；野生動物算自然）。
- 辨識在手機本地進行（TFLite / Core ML），不連網。
- 手牌＝每個人自己手機相簿最新 5 張照片（只取相機拍的照片，過濾截圖；近期照片，建議 7 天內）。
- 手牌最左邊是「拍照」牌。
- 沒有每日上傳張數上限。

### 出牌餵食
- 點一張牌 → 照片舉起，寵物在下方等待 → 「餵給寵物」或「放回」。
- 餵食立即生效（沒有發酵桶、沒有照片壞掉）。
- 「現在想吃」（原「今天想吃」）：每 2 小時換一次，台灣時間偶數整點換、以伺服器時間為準；依寵物偏愛類別抽，不和上一個時段一樣（2026-11-05 定案，`WantSchedule`）。狀態欄倒數之後再做。
- 命中「現在想吃」的類別：寵物開心跳起；沒命中：中性的「嗯…？」（不要用難過的表情）。
- 每餵一張回心：命中 +1 顆、沒命中 +0.5 顆（2026-11-05，以 `docs/design/blockpet-economy-spec.md` 為準）。
- 餵出去的照片**自動分享到營地**，成為營地最新照片（沒有分享按鈕）。
- 出一張牌後，手牌收起，底部變成：相簿（顯示剩餘張數，點了重新展開手牌）、拍照、聊天（未讀數）。
- 冷卻（2026-10-17 定案）：出照片牌與相機拍照餵食共用同一個冷卻（10 分鐘，2026-10-29 定案，`PhotoCooldown`）。出牌後手牌收起、底部變成相簿／拍照／聊天；「相簿」打開遊戲裡的相簿頁（隨時可按）；冷卻中拍照顯示倒數、不能按；冷卻結束後手牌自動展開。（與設計檔 v8「點相簿再出一張」不同，以此為準）

### 愛心與死亡
- 愛心 0～5 顆，以半顆為單位顯示。
- 約每 5 小時沒人餵掉半顆（48 小時沒人餵剩半顆，約 50 小時死亡）。
- 房間任何成員餵食都算。
- 掉心以伺服器時間計算。
- 剩 2 顆、剩半顆時推播全房間。
- 愛心 0 → 死亡 → 從房間帳戶付 100 金幣復活（2026-10-28 定 100 金幣；2026-11-06 改成在復活視窗直接付金幣，不再買藥水、商店沒有「道具」分頁；`EconomyRules.RevivePrice`），完全恢復；圖鑑紀錄不撤銷。
- 商店分頁：家具／環境／穿搭／寵物蛋（2026-11-06：「裝飾」「道具」刪除，「環境」保留不改名「擴建」；11-07 新增「穿搭」）。
- 穿搭（設計文件 5.11 ⑧）：寵物穿戴的東西，用營地金幣買；只是打扮，不影響任何數值；身體長相不賣。部位頭／臉／脖子／側邊，同部位一次一件。品項與暫定價格在 `Resources/Shop/outfits.json`；穿著存 `Rooms/{room}/outfit`，營地共用（待決 36 暫定）；換穿只在商店；拍立得寵物貼紙先不顯示穿搭。
- 愛心等級影響寵物待機行為、移動速度與收益乘數：★1～★5 對應 ×0.6 / 0.8 / 1.0 / 1.2 / 1.4，半顆捨去（即時套用；數字只定義在 `EconomyRules`）。

### 經濟
- 每張照片收益：沒命中 +1；命中現在想吃 +5 × 愛心乘數（先回復愛心，再用回復後的愛心算）。經濟數值以 `docs/design/blockpet-economy-spec.md` 為準。
- 沒有角色身份加成、沒有 7/3 分帳。
- 金幣歸房間：所有成員賺的金幣進同一個房間帳戶；家具、擴建、復活都從房間帳戶扣款。要記錄每筆是誰賺、誰花的。
- 付費項目只有：家具、營地擴建、寵物穿搭（2026-11-07 第 7 節修改原則：穿戴物可以賣、只是打扮）、寵物蛋（抽蛋）。寵物身體長相不賣。

### 進化與寵物
- 進化條依五類照片顏色分段累積。
- 進化條集滿 100 張照片可進化（2026-10-29 定案），從空間第一張照片開始算、空間裡每個人餵的都算；集滿後停在「可進化」，等第 10 步進化系統。
- 餵食類別比例決定進化分支；不夠可愛的寵物可以靠餵照片養成好看。
- 寵物可用付費抽蛋取得；買到的蛋仍需餵照片才會成長。
- 抽蛋是機率型商品：必須能公告機率、記錄保底計數。

### 營地與社群
- 一個房間共用一個營地、一隻寵物。
- 首頁右下（手牌最右）是營地最新照片：比手牌大、金框發光、只能看不能出。點開進入分割畫面：
  - 上：返回＋營地照片縮圖列
  - 中：大照片（題目標籤、新、發布者與說明、最近 2 則留言）、留言輸入
  - 下：縮小的營地與寵物，寵物會對照片做反應
  - 營地右側中間半透明快門圈圈（2026-10-30 定案 G）：點了大照片變成相機畫面（右上翻轉鏡頭），再按快門拍下直接餵寵物（共用拍照冷卻），新照片排最前面
- 沒有預設反應按鈕（好想吃／想去等已拿掉）。
- ~~分割畫面（5.16）、照片檢視（5.14 ⑥）~~：2026-11-07 由拍立得分割畫面取代（設計文件 5.26，`PolaroidScreen`），舊程式已刪除。
- 拍立得分割畫面（5.26）：首頁最新照片貼紙、相簿、聊天室「到營地看這張」都打開它，左右滑換張不循環。照片正方形 318；照片左下最新 2 則留言（留言就是聊天室回覆這張照片的訊息）；下方面板兩頁左右滑（寵物頁：營地、愛心、進化條，想吃的類別就跳、不是就歪頭；裝飾頁：貼紙／畫框／濾鏡），卡片右下編輯鈕也能切換（2026-11-08）；切到裝飾頁時，自己拍的照片留言框自動變成寫標題（不跳鍵盤），標題旁的編輯筆拿掉（2026-11-08 使用者決定，和設計 5.26 不同）；濾鏡只有萊卡、富士底片、Y2K（CCD，右下日期戳），預設不用、再點一次取消；大家都能貼貼紙（每人每張最多 3 個，暫定），自己的可以拖、可以撕；標題只有拍照的人能改，畫框、濾鏡營地成員都能換（2026-11-08 使用者決定，和設計 5.26 不同）；貼紙、畫框、濾鏡、標題存在 `Rooms/{room}/polaroid`。下載／分享的是整張拍立得（不含留言、不加浮水印，`PolaroidExport`＋`PhotoExport`）。待決 35 的暫定值在 `PolaroidRules`（標題字型暫用 Noto Sans、拍照的人撕別人貼紙還沒做）。
- ~~今日題目~~：2026-11-06 刪除（設計文件第 2 節第 4 項）。
- ~~裝飾（撿東西）~~：2026-11-06 刪除（設計文件 5.12），商店不再有「裝飾」分頁。
- 寄明信片：見設計文件 5.21（2026-11-08 改版，取代旅行）與下方「寄明信片」；玩家不能直接參觀別的營地。
- 離開空間：其他成員繼續養；只剩自己一個人時也能離開，空間整個刪除（寵物、照片、聊天，無法復原；2026-11-04 定案）。

### 圖鑑（設計文件 5.23）
- 營地共用一本、分系列、每系列 3 格（彩虹型、極致型、進化型，沒有稀有；2026-11-05 從 7 格改），進化那一刻記；同一格收好幾次記 ×N。
- 進化型的判斷（設計文件 5.17 ②，`DexRules.TypeFor`）：主色超過 50%＝極致型；五色都有且主色不到 30%＝彩虹型；其他＝進化型。
- 格子沒有底色和框，一排 3 格（11-05）：收到＝寵物＋名字；還沒收到＝只有剪影（黑 22%），點了小卡才看名字和怎麼養。
- 系列先照設計稿：BowBow、貓咪、兔子、萬聖節（2026-11-05 定，`DexRules`）；全部系列都顯示，營地沒有的品種只放「去商店抽蛋」；還沒有品種系統，現在的寵物都算 BowBow（`DexRules.DefaultSeries`），BowBow 的說明寫「收滿送蛋」。每個系列都放 7 格剪影（2026-11-05 使用者決定，和設計「沒有的品種只放去商店」不同；`DexRules.ShowCellsForAllSeries`）；寵物圖和剪影暫用 Zapup。上方系列分頁（篩選）拿掉，頂部只留返回、標題、總進度（2026-11-05 使用者決定）。
- 新的一格全營地 +100 金幣（暫用值，`EconomyRules.DexNewCellCoins`）；收滿一個系列送免費抽一次寵物蛋（2026-11-05 定案），先記在 `Rooms/{room}/shop/free_egg_draw`，抽蛋（5.24）做好時扣；收滿的系列標題旁有金色「收滿」。
- `DexScreen` 執行時建立；資料 `Rooms/{room}/dex`；進化系統還沒做，用 BlockPet/Debug/圖鑑 記一筆測試。

### 寄明信片（設計文件 5.21，2026-11-08 取代旅行）
- 「旅行」改叫「寄明信片」，但右上選單的字維持「旅行」（2026-11-08 使用者決定）；去好友營地＝送明信片；會長大的地圖、路、路程時間、寵物在路上、客人來玩都沿用（`TravelMapGen`、`TripRules`）；去過的營地大頭針右上是小郵票（×N）。
- 好友全部用抽的：每營地每天免費 1 次（台灣時間 0 點換日），之後金幣（設計稿 50）；配對最常拍的類別一樣優先、國家隨機（手機地區設定，2026-11-08 使用者決定）；已是好友、封鎖過（雙向）、等確認中的不會抽到；配對卡只有營地名稱、寵物、品種、成員數、最常拍的類別、國家。雙方都按「加好友」才成為好友，略過不通知，24 小時失效（暫定）。好友上限 10，100 金幣解鎖 +1 格（使用者暫定）；數字在 `Resources/Postcard/postcard_settings.json`。營地代碼加好友、邀請信封、輸入框、營地資訊頁的藍色營地代碼都已刪除。
- 寄明信片：點好友 → 選一張照片；有人臉的不能寄（iOS Vision／Android ML Kit，`FaceDetector`）；裝飾過的拍立得直接用（「用這張拍立得寄出」「再編輯」），沒裝飾過的打開拍立得畫面；寄出當下那一版（JPG）。寵物送到後回家，帶回一張對方營地的風景明信片（自動產生）。2026-11-08 使用者決定拿掉回寄、各寄各的（和設計文件 5.21 ④-5、④-6 的回寄不同，以此為準）：想收到對方的照片，要等對方用自己的寵物寄過來。收到的明信片只在護照，不進相簿、不能餵；遊戲存出去的圖（BlockPet 相簿）不會變成手牌。
- 封鎖：刪掉兩邊好友、地圖那塊地消失、以後不會再配到；檢舉存進 `Reports`（審核方式待定）。
- 推播還沒做（2026-11-08 使用者決定先做 App 內通知）。

### 相機（設計文件 5.27，2026-11-08）
- 底部三顆不變（翻轉鏡頭／快門／退出）；快門上方鏡頭列：魚眼開關｜1× 2× 3×（`CameraLensBar`）。
- 縮放 1×～5×：裁切畫面中間的數位縮放，預覽和照片一樣；兩指連續縮放；翻轉鏡頭回 1×；不做 0.5×。
- 魚眼：只套在顯示上（`FisheyeImage`＋`Resources/Shaders/UIFisheye`），照片存原圖＋`PhotoMeta.fisheye`；辨識用原圖；開關用 PlayerPrefs 記住；可以和拍立得顏色濾鏡疊用；2026-11-08 使用者改成全片幅魚眼（像 Sony FE 8-14mm：畫面填滿、沒有圓形暗角，中間稍微放大、邊緣壓縮），臉不能變形（11-08）：中間一個圓（短邊一半的 60%）只等比放大 1.4 倍、不拉歪，彎曲集中在外圈（`FisheyeImage` 的三個數值）。

### 佈置營地（設計文件 5.28，2026-11-08）
- 斜角格子 60×30，數值以 `docs/decorate/decorate_spec.json` 為準（`GridMath`）；每個營地一張格子表（`Resources/Camp/CampGrid_forest`），在 Unity 用滑鼠標存在／不能放，擴建（花田、湖畔）先留介面。
- 底座：帳篷 2×2；吊床、地墊、屏風 2×1；營火、畫架、燈籠、信箱 1×1；串燈是掛點，先不做。前後 i+j+w+d，寵物同一套。
- 入口只有右上選單「佈置」和商店「去擺放」（2026-11-08 使用者：不另做按鈕）；拖曳擺放（使用者要求，設計是點綠格，兩種都可以）；佈置時狀態欄、照片貼紙、底部按鈕收起來（`DecorModeSettings`）；舊的自由擺放已刪。
- 擺法存在 `Rooms/{room}/decorations/{id}` 的 `gi`、`gj`，大家看到一樣；沒格子座標的舊家具算「還沒擺出來」。移動場上的家具沿用「只有擺的人能動」（暫定，待確認）。

- 狀態欄只有一列：寵物頭像（Lv）、名字、愛心、想吃標籤／進化條＋百分比、金幣（點金幣進商城）。

- 每日 5 張上傳上限
- 許願卡、小遊戲、刮刮樂、任何押注
- 分享按鈕（改為自動分享）

- 棲地召喚、側視路徑圖房間、可進入家具（完整版系統，簡化版先不做）

## 待定（遇到時先問）

- 房間金幣的花費權限：任何成員都能花，還是需要其他成員同意。
- 進化分支數量與階段數。
- 免費蛋的取得方式；畢業寵物留在營地還是只進圖鑑。
- 抽蛋機率表與保底次數。
- 拉肚子要不要保留。
- 好友是房間對房間還是個人；明信片每人或每房每天一次。

## 開發順序（MVP）

依序進行，每一步做完可在 Editor 測試再進下一步：

1. **房間資料結構**：在 Firebase 建立 Room（成員、寵物、房間金幣、營地動態、聊天）；登入後建立或加入房間；把本地存檔的寵物／愛心／金幣搬到房間底下（拍照冷卻保留）。
2. **相簿手牌**：讀取相簿權限、取最新 5 張相機照片（過濾截圖）、手牌排列與舉起／放回；無權限時的空狀態。
3. **出牌餵食與回饋**：辨識結果 → 命中判定 → 寵物反應動畫與台詞 → 結算愛心、進化能量、金幣。
4. **首頁狀態欄**：一列版面；愛心半顆顯示；五色分段進化條。
5. **出牌後狀態**：手牌收起、底部相簿／拍照／聊天，點相簿重新展開。
6. **愛心計時**：伺服器時間掉心、回心、死亡與復活、推播。
7. **自動分享與最新照片**：上傳、營地動態、最新照片卡、連續發佈合併。
8. **分割畫面**：縮圖列、大照片、留言、縮小營地寵物反應。

10. **進化分支**：依類別比例判定分支與階段、進化演出。
11. **商城與佈置**：金幣入口、家具／擴建、佈置模式拖曳擺放。
12. **抽蛋**：內購、機率表、保底、孵化演出、機率公告頁。
