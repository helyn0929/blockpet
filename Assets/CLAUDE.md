# Blockpet（簡化版）— 給 Claude Code 的專案說明

這是一款用手機照片養寵物的社交手遊。Unity 2D，直式手機。
玩家用自己相簿裡的照片當手牌，出牌餵給房間共用的寵物；寵物依照片類別給回饋、進化；餵出去的照片自動分享到營地，大家可以留言。

## 工作方式

- 介面設計以 claude.ai 設計檔「Blockpet 簡化版遊戲畫面」的「首頁 v8 照片分割」為準（https://claude.ai/artifact/BhqLuHp9n1MniNXyypAYim）。

- 用繁體中文回覆、寫註解與 UI 文字。
- 不要把整段程式碼貼在對話裡，直接修改專案檔案。
- 改動前先讀既有程式，延用既有寫法，不要重寫已完成的系統。

## 現有程式（2026-10-17 盤點，Unity 2022.3.62f3、URP、Firebase）

- 可直接沿用：`FirebaseManager`（Google／Apple／訪客登入、Realtime Database）、`ChatUIHandler`／`ChatMassage`（聊天室，目前寫在 `ChatRoom` 節點）、`CameraController`（WebCamTexture 拍照）、`AlbumUI`（相簿依日期分組）、`PetAnimationEvents`、`FeedController`（餵食動畫流程）、`EconomyManager`（金幣與數字跳動 UI）。
- 需要改：
  - 所有遊戲資料目前存在手機本地（`SaveManager` 的 save.json、`PlayerPrefs`）。寵物、愛心、金幣、照片動態要改成存在 Firebase 的房間底下，讓成員共用。
  - `PetHealthManager`：目前是 24 小時連續秒數、用手機時間計算；改成 0～5 顆（半顆為單位）、每 5 小時 −0.5、伺服器時間。
  - `EconomyManager`：目前每張固定 +50、存個人 PlayerPrefs；改成 +1／+5×愛心乘數，存房間帳戶。
  - `CameraController`：拍照冷卻保留（目前程式是 30 秒）；沒有每日張數限制。
  - `PetCollectionManager`：集滿後隨機換寵物是佔位邏輯，之後換成進化分支與孵化。
  - `BulletinManager`（7 張照片看板）：改成營地最新照片與分割畫面。
  - 聊天室要從全域 `ChatRoom` 改到各房間底下。
- 目前沒有「房間」的資料結構，需要新增。
- 發酵桶已於 2026-10-17 移除；舊程式裡沒有角色身份、7/3 分帳，不用清理。
- 寵物移動使用既有的 NavMeshPlus 設定。
- 一次只做一個任務；做完說明改了哪些檔案、如何在 Editor 測試。
- 遇到下方「待定」的規則，先問我，不要自己決定。

## 已定案的遊戲規則

### 照片與手牌
- 照片五大類別：美食、自然、城市、生活人物、運動戶外。
- 辨識在手機本地進行（TFLite / Core ML），不連網。
- 手牌＝每個人自己手機相簿最新 5 張照片（只取相機拍的照片，過濾截圖；近期照片，建議 7 天內）。
- 手牌最左邊是「拍照」牌。
- 沒有每日上傳張數上限。

### 出牌餵食
- 點一張牌 → 照片舉起，寵物在下方等待 → 「餵給寵物」或「放回」。
- 餵食立即生效（沒有發酵桶、沒有照片壞掉）。
- 命中「今天想吃」的類別：寵物開心跳起；沒命中：中性的「嗯…？」（不要用難過的表情）。
- 每餵一張回半顆心。
- 餵出去的照片**自動分享到營地**，成為營地最新照片（沒有分享按鈕）。
- 出一張牌後，手牌收起，底部變成：相簿（顯示剩餘張數，點了重新展開手牌）、拍照、聊天（未讀數）。
- 冷卻（2026-10-17 定案）：出照片牌與相機拍照餵食共用同一個冷卻（目前 30 秒，`PhotoCooldown`）。出牌後手牌收起、底部變成相簿／拍照／聊天；「相簿」打開遊戲裡的相簿頁（隨時可按）；冷卻中拍照顯示倒數、不能按；冷卻結束後手牌自動展開。（與設計檔 v8「點相簿再出一張」不同，以此為準）

### 愛心與死亡
- 愛心 0～5 顆，以半顆為單位顯示。
- 約每 5 小時沒人餵掉半顆（48 小時沒人餵剩半顆，約 50 小時死亡）。
- 房間任何成員餵食都算。
- 掉心以伺服器時間計算。
- 剩 2 顆、剩半顆時推播全房間。
- 愛心 0 → 死亡 → 用房間金幣復活，完全恢復；圖鑑紀錄不撤銷。
- 愛心等級影響寵物待機行為與收益乘數：★1～★5 對應 ×0.6 / 0.8 / 1.0 / 1.2 / 1.4（即時套用）。

### 經濟
- 每張照片收益：沒命中 +1；命中今天想吃 +5 × 愛心乘數。
- 沒有角色身份加成、沒有 7/3 分帳。
- 金幣歸房間：所有成員賺的金幣進同一個房間帳戶；家具、擴建、復活都從房間帳戶扣款。要記錄每筆是誰賺、誰花的。
- 付費項目只有：家具、營地擴建、寵物蛋（抽蛋）。不賣角色服裝。

### 進化與寵物
- 進化條依五類照片顏色分段累積。
- 餵食類別比例決定進化分支；不夠可愛的寵物可以靠餵照片養成好看。
- 寵物可用付費抽蛋取得；買到的蛋仍需餵照片才會成長。
- 抽蛋是機率型商品：必須能公告機率、記錄保底計數。

### 營地與社群
- 一個房間共用一個營地、一隻寵物。
- 首頁右下（手牌最右）是營地最新照片：比手牌大、金框發光、只能看不能出。點開進入分割畫面：
  - 上：返回＋營地照片縮圖列
  - 中：大照片（題目標籤、新、發布者與說明、最近 2 則留言）、留言輸入
  - 下：縮小的營地與寵物，寵物會對照片做反應
- 沒有預設反應按鈕（好想吃／想去等已拿掉）。
- 今日題目：每天 5 題，首頁左側直排；第一個拍到的人站上那一格。
- 旅行：到別人的營地參觀（唯讀），可以加朋友；每天可以送一次明信片給朋友。

### 首頁介面
- 狀態欄只有一列：寵物頭像（Lv）、名字、愛心、想吃標籤／進化條＋百分比、金幣（點金幣進商城）。
- 右上收合選單：旅行、圖鑑、設定（預設收起）。
- 中央大片空地留給佈置與寵物。

## 不要做（已刪除的設計）

- 發酵桶、照片壞掉、FermentSlot
- 角色身份（半獸人主廚等五種身份）與身份加成
- 7/3 分帳
- 每日 5 張上傳上限
- 許願卡、小遊戲、刮刮樂、任何押注
- 分享按鈕（改為自動分享）
- 狀態欄上的相簿／聊天／圖鑑／設定圖示、「⋯」選單
- 棲地召喚、側視路徑圖房間、可進入家具（完整版系統，簡化版先不做）

## 待定（遇到時先問）

- 房間金幣的花費權限：任何成員都能花，還是需要其他成員同意。
- 「今天想吃」每天怎麼產生。
- 進化分支數量與階段數。
- 免費蛋的取得方式；畢業寵物留在營地還是只進圖鑑。
- 抽蛋機率表與保底次數。
- 拉肚子要不要保留。
- 好友是房間對房間還是個人；明信片每人或每房每天一次。
- 今日題目怎麼產生、是否用辨識判斷符合題目。

## 開發順序（MVP）

依序進行，每一步做完可在 Editor 測試再進下一步：

1. **房間資料結構**：在 Firebase 建立 Room（成員、寵物、房間金幣、營地動態、聊天）；登入後建立或加入房間；把本地存檔的寵物／愛心／金幣搬到房間底下（拍照冷卻保留）。
2. **相簿手牌**：讀取相簿權限、取最新 5 張相機照片（過濾截圖）、手牌排列與舉起／放回；無權限時的空狀態。
3. **出牌餵食與回饋**：辨識結果 → 命中判定 → 寵物反應動畫與台詞 → 結算愛心、進化能量、金幣。
4. **首頁狀態欄**：一列版面；愛心半顆顯示；五色分段進化條。
5. **出牌後狀態**：手牌收起、底部相簿／拍照／聊天，點相簿重新展開。
6. **愛心計時**：伺服器時間掉心、回心、死亡與復活、推播。
7. **自動分享與最新照片**：上傳、營地動態、最新照片卡、連續發佈合併。
8. **分割畫面**：縮圖列、大照片、留言、縮小營地寵物反應。
9. **今日題目**：每日 5 格、搶先佔領、題目相片集。
10. **進化分支**：依類別比例判定分支與階段、進化演出。
11. **商城與佈置**：金幣入口、家具／擴建、佈置模式拖曳擺放。
12. **抽蛋**：內購、機率表、保底、孵化演出、機率公告頁。
13. **旅行與好友**：參觀別人營地、加朋友、每日明信片。
14. **圖鑑與設定**。
